================================================================================
GIT BRANCHING GUIDE: วิธีทำงานแบบแยกกิ่ง (Feature Branching)
บันทึกเพื่อกันลืมสำหรับโปรเจกต์ GHP Management
================================================================================

1. การตรวจสอบสถานะปัจจุบัน
   - ดูว่าอยู่กิ่งไหน และมีไฟล์ไหนถูกแก้บ้าง:
     git status

   - ดูรายชื่อกิ่งทั้งหมด (กิ่งที่มีดอกจัน * คือกิ่งที่ใช้อยู่):
     git branch

2. การสลับกิ่งทำงาน
   - สลับไปกิ่งหลัก (สำหรับอัปเดตเซิร์ฟเวอร์):
     git checkout main

   - สลับกลับมากิ่งที่กำลังพัฒนา (ZKTeco Refactor):
     git checkout feature/zkteco-refactor

3. การสร้างกิ่งใหม่ (กรณีเริ่มทำฟีเจอร์ใหม่ในอนาคต)
   - สร้างกิ่งใหม่จากกิ่งปัจจุบันและสลับไปทันที:
     git checkout -b feature/your-new-feature-name

4. การเก็บงาน (Save Work)
   - ทำทุกครั้งที่ต้องการบันทึกประวัติ หรือก่อนสลับกิ่ง:
     git add .
     git commit -m "เขียนอธิบายสั้นๆ ว่าแก้อะไรไป"

5. การรวมงานกลับเข้ากิ่งหลัก (เมื่อทำเสร็จและทดสอบผ่านแล้ว)
   1. git checkout main          (สลับไปกิ่งหลัก)
   2. git pull origin main       (ดึงโค้ดล่าสุดจากเซิร์ฟเวอร์มาอัปเดต)
   3. git merge feature/zkteco-refactor  (เอางานใหม่มารวม)
   4. git push origin main       (ส่งโค้ดที่รวมแล้วขึ้นเซิร์ฟเวอร์)
